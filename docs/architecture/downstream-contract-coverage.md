## Port and operation matrix

The error column is the exact closed union of operation codes for that port.
The problem catalog owns each code's type, HTTP status, retryability, permitted
side-effect-state set, and CLI exit mapping; each operation owns the one exact
side-effect state for every code it declares. Read-only and no-side-effect
operations therefore report `none` even when the same code is used by a
mutating operation. Every RFC 9457 problem carries its exact port and operation
identity so a consumer can validate that mapping externally. Port-specific
product schemas named below are complemented by the exact closed request/result
and field-value schemas in the type catalog and their canonical valid and denial
payloads in the fixture catalog.

Each `Exact registry projection` is mechanically checked against its port row.
It cites every exact registry contract path, request/result contract ID,
promised schema ID, and applicable protocol-profile ID. Protocol-profile IDs
resolve transitively to the profile's closed `repoPaths` in
`protocol-profiles.json`; those paths are not duplicated in every row. Removing
any required authority token fails the downstream contract validator's
adversarial coverage mutation.

## Closed resolution of previously ambiguous boundaries

- Native Agent Spec is the only selectable native output. WayFlow 26.1.2 is
  exact locked compatibility evidence only.
- AD-06 owns the generic OpenClaw renderer. AD-17 owns the ByteDesk OpenClaw
  migration map, slug migration, full-catalog comparison, and cutover.
- The Promotion Coordinator is the sole logical DesiredStateStore writer and
  the only actor permitted to dispatch a Capability Verifier check.
- Isolated mode dispatches and verifies capability before switch authorization.
  Guarded mode dispatches after provisional switch and active readback, before
  target-state CAS.
- Host physical state is decided by the durable journal plus exact active
  readback. It is never inferred from intent, filenames, process age, or desired
  state alone.
- External consumer implementation details enter only through exact
  `bytedesk.external-input-lock/1` artifacts with
  `compatibilityEvidenceOnly: true`; none becomes core schema, renderer,
  identity, grant, credential, policy, or runtime authority.

With these closures, the downstream contract surface is complete and ready for
implementation without adapter-specific protocol invention.
